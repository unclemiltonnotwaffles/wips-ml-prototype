1 · Problem & objective

IEEE 802.11 Deauthentication management frames can be used in denial-of-service activity by forcing wireless clients to disconnect. Detecting the frame type alone is not enough: legitimate network activity can also contain Deauthentication frames.

Objective: train and evaluate a binary classifier for the AWID3 labels in scope:

0
Normal
1
Deauth

All other AWID3 attack labels were excluded from this binary experiment. The model classifies individual packet records; it does not yet make event-level attack decisions.

6 · False-positive investigation

3,774 of 3,986 false positives (94.68%) came from two Normal-labelled RogueAP captures.

All 3,774 RogueAP false positives shared:

  • wlan.fc.type = 0 (management)
  • wlan.fc.subtype = 12 (Deauthentication)
  • frame.len = 86
  • wlan.fc.protected = 0
Key finding: the dominant error is structured, not random. Normal-labelled records in these captures contain Deauthentication management frames. A Deauthentication frame by itself does not prove malicious activity.

All signatures matched, but repeated feature signatures can map to multiple packets. The context export includes available timestamps, frame numbers, addresses, sequence numbers, reason-code fields and labels. These matches are candidate sets, not guaranteed one-to-one packet identities.

8 · Main limitations

  • Only two independent Deauth captures appear in the held-out test partition. This is insufficient for strong claims about unseen attack environments.
  • The validation split also contains only two Deauth capture groups.
  • The model predicts individual records, not attack episodes or sustained floods.
  • The Normal-labelled RogueAP records require source-label semantics review before changing labels, features or model design.
  • The test set is highly imbalanced; accuracy alone would be misleading.
Scope boundary: this is an offline packet-level WIDS experiment. It does not perform live monitor-mode capture, transmit deauthentication frames, disconnect clients, or enforce access-point blocking.

9 · Next research steps

  1. Verify AWID3 label semantics for the affected RogueAP records.
  2. Inspect original packet context, including addresses, timestamps, sequence numbers and reason codes.
  3. Build a broader capture-grouped validation set with more independent Deauth sessions.
  4. Develop temporal/event-level features and measure false alarms per time interval.
  5. Evaluate on independent captures and document threshold trade-offs.
  6. Keep any authorised mitigation integration separate, reversible and independently tested.

10 · Conclusion

The Random Forest baseline separates many Deauth-labelled records from Normal records on the held-out AWID3 partition, with 99.05% recall. Its 66.88% precision and concentrated RogueAP false positives expose a key weakness: packet-level frame signatures are not sufficient to establish malicious intent.

Research takeaway: move from isolated packet classification toward context-aware, capture-independent, temporal detection before claiming operational WIDS performance.

Reproducibility

Dataset: AWID3 CSV export. Model: scikit-learn Random Forest. Split unit: source capture file. Evaluation: complete untouched test partition, chunked at 250,000 records. Random state: 42.
